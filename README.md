# 🧰 Essential Developer Tools

Here is a breakdown of the key tools every developer should have in their toolkit:

- **Git & GitHub**
  - **Category:** Version Control System & Collaboration Platform
  - **Primary Use Case:** Tracking source code changes, collaborating with teammates, and managing project repositories.
  - **Key Feature:** Branching and Pull Requests for smooth team integration.

- **Visual Studio Code (VS Code)**
  - **Category:** Source Code Editor
  - **Primary Use Case:** Writing, debugging, and editing code across various programming languages like Web Dev, Python, and Flutter.
  - **Key Feature:** Extensive extension marketplace (Prettier, GitLens, Live Server).

- **Postman**
  - **Category:** API Development & Testing
  - **Primary Use Case:** Sending HTTP requests, inspecting responses, and testing backend endpoints.
  - **Key Feature:** Automated API testing and clear request documentation.

- **Figma**
  - **Category:** UI/UX Design & Prototyping
  - **Primary Use Case:** Creating wireframes, high-fidelity UI designs, and interactive prototypes for web and mobile apps.
  - **Key Feature:** Real-time multi-user design collaboration.

We welcome contributions from all GDG campus members! Follow these steps to contribute to this guide:

1. **Fork the Repository**
   - Click the **Fork** button at the top right of this page to create your own copy.

2. **Clone Your Fork**
   - Open your terminal and run.
     ```bash
     git clone [https://github.com/JayTiwari88/GDGOC-FIRST-YEAR-GUIDE.git](https://github.com/JayTiwari88/GDGOC-FIRST-YEAR-GUIDE.git)
     ```

3. **Create a Feature Branch**
   - Create a new branch for your edits.
     ```bash
     git checkout -b feature/AddYourFeature
     ```

4. **Commit Your Changes**
   - Write a clear commit message detailing your changes.
     ```bash
     git commit -m "Add beginner Flutter installation steps"
     ```

5. **Push and Open a Pull Request**
   - Push your changes to GitHub and submit a Pull Request (PR).
     ```

- **Documentation Standards:**
  - Please ensure all updates follow valid GitHub Flavored Markdown (GFM) formatting.
  - Keep explanations beginner-friendly, concise, and structured.
